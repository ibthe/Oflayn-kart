# Архитектура Georgia Offline

```text
Compose UI
  ├── Map / Discover / Route / Saved / Tools / Settings
  └── local settings
       ├── MapRenderer ── Mapsforge adapter
       ├── PoiRepository ── local SQLite substring search
       ├── OfflineRouter ── local memory-mapped A* graph (car / motorcycle / 4×4 / bike / foot)
       ├── DemRepository ── lazy Copernicus GLO-90 tile cache + route profiles
       ├── TrackRecorder ── foreground GPS filter + crash-safe GPX repository
       ├── TripPlanRepository ── local day-based itinerary and stop notes
       ├── GuidebookRepository ── static offline regional guidebook
       ├── EmergencyPanel ── fresh coordinates, battery and user-confirmed 112 dialer
       └── StorageBackend ── internal + app-specific removable SD storage

GitHub Actions data pipeline
  ├── Geofabrik primary / OSM France fallback Georgia country PBF + MD5 verification
  ├── Osmosis + Mapsforge Map Writer (pinned 0.25.0)
  ├── mapsforge .map with preferred language variants en/ru/ka
  ├── PyOsmium -> SQLite POI database (nodes + closed ways + multipolygon relations)
  ├── Copernicus WorldDEM-90 -> verified compressed elevation tiles with explicit no-data cells
  ├── SHA-256 manifests for map, POI database and DEM
  └── cached assets -> app/src/main/assets/

APK assets
  ├── Georgia vector map (.map) — generated by CI in v0.4.0
  ├── POI + multilingual names (.sqlite) — generated from the same OSM PBF
  ├── compact road graph + five routing profiles — generated by CI and bundled when available
  ├── Copernicus GLO-90 DEM tiles — generated by CI; route profiles at runtime
  ├── optional satellite mosaic — planned
  └── data manifests + license notices
```

## Key decisions

- The installed app has no network permission and no network tile source.
- Map data are generated during CI, not downloaded by the installed app.
- One APK is the selected distribution format; the map binary is placed in Android assets before Gradle packaging.
- `PoiRepository` copies the SQLite POI asset to app-private storage after checking SHA-256 and database row availability; local search uses parameterized SQL and the normalized multilingual `search_text` field.
- `MapFileRepository` installs the bundled map or imports a user map into the selected internal or removable app-specific storage volume. It validates the map and preserves the previous copy until the new path is saved. A bundled map is refreshed from the APK when its SHA changes; user-imported maps are not overwritten by bundled updates. SD-card paths are resolved only from mounted volumes returned by Android, not arbitrary stored paths.
- The CI restores the most recent verified country-map cache before contacting OSM providers. When a refresh is requested or the cache is missing, Geofabrik is tried first and the OpenStreetMap France Georgia-country mirror is the fallback. Each downloaded PBF is checked against that provider’s MD5. The exact provider and checksum are recorded in the map build manifest. Weekly scheduled and manual refreshes update the cache; normal code pushes use the last verified map.
- The source ZIP does not include the large binary map. It is generated by GitHub Actions and ends up in the APK artifact.
- Mapsforge is the map renderer and map format. `MapsforgeMapSurface` uses a single `MapFile` for one selected map-label language or a `MultiMapDataStore` of language-specific `MapFile` readers when multiple map-label languages are enabled. Routing currently uses a compact, memory-mapped A* road graph with five travel profiles (car / motorcycle / 4×4 / bicycle / foot); BRouter remains a comparison candidate, not an assumed replacement.
- Language variants are requested from the writer as `en,ru,ka`; a name variant is stored only if the corresponding OSM tag exists. There is no automatic translation. The user independently enables map-label languages; Mapsforge `MultiMapDataStore(RETURN_ALL)` combines one reader per enabled language so the renderer can place labels from all selected variants. The language used in place lists is a separate preference.
- The SD-folder picker is present, but direct map extraction to external SAF storage is not implemented yet. An explicit map-disable setting is persisted across launches, users can restore the APK-bundled map, and the repository checks free space before copying a large asset.

## Offline map storage

- `MapFileRepository` lists internal app-private storage and mounted removable SD volumes through `getExternalFilesDirs`.
- Bundled maps are installed and user-imported maps are validated on the selected volume. Imported maps are copied and validated before settings switch to the new path; the previous copy is deleted only after the new path is saved.
- SD storage is app-specific (`Android/data/.../files/maps`), needs no broad storage permission, and is removed by Android when the app is uninstalled. A removed card makes its map unavailable until reconnected or the user selects another volume.

## Compact navigation metrics

- The active navigation footer remains collapsed by default and can expand to show fresh GPS speed, GPS altitude, course and coordinates. Stale last-known fixes are never presented as live values.

## Offline elevation model

- CI downloads 24 one-degree Copernicus WorldDEM-90 COG tiles for the Georgia map bounds, converts them to deterministic gzip-compressed little-endian int16 grids, and verifies tile checksums and dimensions before APK packaging.
- `DemRepository` lazily loads at most four 1200×1200 tiles and samples route geometry at roughly 100 m intervals. `ElevationProfile` reports approximate ascent, descent, minimum and maximum elevation.
- The source is a 90 m digital surface model (DSM), not bare-earth terrain or road-surface elevation. Attribution is shown in About; elevation profiles are omitted when tiles are unavailable.

## Offline emergency panel

- `EmergencyPanel` shows only a fresh GPS fix, coordinate accuracy and battery percentage.
- It can copy coordinates, open the system share chooser, or open the dialer for Georgia's 112 emergency number. The app never places calls or sends messages automatically.

## Offline regional guidebook

- `GuidebookRepository` provides static, offline summaries for eight Georgian regions, with highlights, recommended seasons and mountain-road cautions.
- The guidebook explicitly avoids presenting static notes as live road status; users are directed to verify official restrictions before departure.

## Offline trip planner

- `TripPlanRepository` stores POI IDs, day/order metadata and per-stop notes locally in an atomic app-private file; an itinerary is limited to 20 stops.
- Places can be added from the catalog or map, reordered within a day, moved to another day, annotated, and routed as a day itinerary using the existing multi-waypoint planner.

## GPX tracks and foreground recorder

- `GpxCodec` securely parses GPX 1.1 track/route points with coordinate validation, external-entity protections and optional descriptions/notes, and exports standards-compliant GPX.
- `TrackRecorder` collects only fresh foreground GPS fixes, filters poor accuracy and near-duplicate points, and keeps recording state at the app root so tab changes do not stop it.
- `TrackRepository` stores imported and recorded GPX files in app-private storage. Import/export uses Android's Storage Access Framework document pickers.
- Saved tracks and their notes can be displayed in the track catalog; a selected continuous segment is drawn on the map and automatically framed. Reverse guidance snaps to the nearest point within 150 m and follows that continuous GPX segment back to its beginning; off-track deviation is reported without silently switching to a road route. Segments separated by GPX gaps are not joined.
- Recovery checkpoints are written to a private hidden GPX file after the first two fixes, then every 10 points or 30 seconds. On startup the app offers to continue, save or discard the unfinished recording; checkpoint generations prevent an older asynchronous write from recreating a completed track.
- Background location is intentionally not requested. Recording pauses when the app leaves the foreground.

## Route-corridor POI search

- `PoiRepository.searchAlongRoute` samples the planned polyline into bounded SQLite windows, then filters candidates against the route geometry within a 2.5 km corridor.
- Results are ordered by route progress, so the list follows the planned direction. Selecting a place allows it to be inserted as a via stop without replacing the destination.

## Pre-ride safety checklist

- Eight checks cover protective gear, tires, brakes/lights, fuel, documents, water/first aid, offline-map readiness and phone/emergency readiness.
- Checked items persist in private app preferences. The checklist is fully offline and exposes a reset action; it does not transmit user data.

## GPS tools (0.2.0)

`ToolsScreen` uses Android `LocationManager` with `GPS_PROVIDER` only after the user taps the GPS start action and grants location permission. Updates are removed when the screen leaves composition or GPS is stopped. The implementation does not request background location or internet access. Compass azimuth uses `Sensor.TYPE_ROTATION_VECTOR`; the local car marker is stored in app-private SharedPreferences. Coordinate formatting is isolated in `GeoFormatting` and covered by unit tests.

## Mapsforge renderer (0.3.0)

- Android dependencies: `org.mapsforge:mapsforge-map-android:0.25.0` and `org.mapsforge:mapsforge-themes:0.25.0`.
- `MapsforgeMapSurface` hosts native `MapView` inside Compose using `AndroidView`. It uses a local `MapFile`, a tile cache and `TileRendererLayer`; no online tile source is configured.
- Local `.map` import uses Android Storage Access Framework and validates Mapsforge header plus Georgia bounding-box intersection.
- `MapFileRepository.installBundledMap` copies the CI-generated APK asset to app-private storage on first run.

## Road graph and routing profiles

- The graph stores access masks in unsigned 8-bit fields; five profiles use bits 1, 2, 4, 8 and 16. Motorcycle access resolves `motorcycle` before `motor_vehicle` and generic `vehicle` tags, excludes track/path classes by default unless explicitly permitted, respects one-way direction, and excludes `horrible` / `very_horrible` / `impassable` surfaces.

- `scripts/road_graph_format.py` is the binary graph specification shared with Kotlin. The compact graph stores directed access masks, road class, unpaved/roundabout/smoothness flags and names.
- The five profiles are car, motorcycle, cautious 4×4, bicycle and foot. OSM `access`, vehicle-specific access, one-way, `surface`, `tracktype` and `smoothness` tags affect graph eligibility and estimated travel speed.
- `horrible`/`very_horrible` smoothness excludes ordinary cars and bicycles; `very_horrible` remains available only to cautious 4×4 and foot with a strong speed penalty; `impassable` is excluded for all profiles. Routes surface warnings instead of presenting rough roads as ordinary roads. Coarse incline-aware speed penalties are applied from OSM `incline` tags; full directional grade modelling and turn restrictions remain outstanding.

## Georgia map generation (0.4.0)

- `scripts/install_mapsforge_writer.sh` checks Osmosis, clones the pinned Mapsforge 0.25.0 source tag, builds the `mapsforge-map-writer:fatJar` task and installs the plugin for the current CI user.
- `scripts/build_georgia_map.sh` retrieves the Geofabrik Georgia country PBF (with OpenStreetMap France fallback) and matching provider MD5, verifies the source, runs `build_poi_database.py` using PyOsmium's disk-backed node-location index to create a SQLite POI database from OSM nodes, closed ways and multipolygon relations, then runs Osmosis `--rb` -> `--mw` using `type=hd`, start position near Tbilisi, start zoom 9, and `preferred-languages=en,ru,ka`.
- The resulting `georgia.map`, `georgia-poi.sqlite` and `georgia-map-build.json` (source, timestamp, source MD5, SHA-256/size/count for both assets, writer version, ODbL attribution) are cached and copied into APK assets.
- `verify_bundled_map.py` checks the map SHA-256, SQLite integrity/row count and POI SHA-256 before Android build; `verify_dem.py` checks all published compressed elevation tiles and explicitly accounts for cells absent from the public bucket; `verify_apk_bundle.py` reopens the APK and verifies map, POI, DEM manifest, tile checksums and raw tile dimensions.
- `verify_offline_manifest.py --include-merged` verifies the final merged manifest after Gradle assembly.

## POI database and local search (0.5.3)

- The same verified country PBF is parsed by PyOsmium using `locations=True` and `sparse_file_array` (disk-backed node-location index). A relation-aware `area()` callback triggers PyOsmium's two-pass multipolygon assembly and adds relation-derived POIs while closed way areas remain indexed once.
- POI records include OSM nodes, closed ways and multipolygon relations, categories, coordinates, OSM tags and `name` / `name:en` / `name:ru` / `name:ka` values where present. Relation-derived area centroids are weighted by outer-ring area and use original relation IDs; full-country duplicate and coverage validation remains required.
- `PoiRepository` validates the generated SQLite asset with SHA-256, copies it to app-private storage, and runs local parameterized SQL search. Selected name variants can be shown together in the results list.
- The POI search index also includes public OSM address, phone, website, opening-hours, cuisine, wheelchair-access and operator/brand tags. The detail card displays only fields actually present in the source.
- The index intentionally uses ordinary SQLite `instr()` over a normalized text field rather than requiring FTS5 on every Android system.
- Relation areas are assembled by PyOsmium's area callback; this performs a second PBF pass and uses the disk-backed node-location index. The POI metadata records whether relation extraction is enabled.
- Public address/contact/business tags (address, phone, website, opening hours, cuisine, wheelchair, internet, operator and brand) are searchable and shown on a POI card when present. `opening_hours` is displayed as source text, not interpreted as live opening status.


## Still planned

- Validate simultaneous language-label rendering, duplicate-label behavior, tile-render performance and memory use on physical Android devices; optimize with a label-only overlay if needed.
- Validate multipolygon relation POIs on the full country PBF and deduplicate overlapping node/way/relation objects.
- Validate relation-derived POIs and deduplicate overlapping node/way/relation objects on a full uncached country PBF; expand categories and amenity details, then consider optional FTS after device compatibility checks.
- Routing turn restrictions and grade-aware costs; compare current engine with BRouter. Road-quality access masks and route warnings are implemented.
- Contour lines and hillshade overlays; DEM tiles and route elevation profiles are implemented.
- Expand the eight-region guidebook, add more offline safety checklists and multi-day itinerary export; trip planning and stop notes are implemented.
- Test SD-card removal/reconnection, low-space failures and large-map migration on physical Android devices; app-specific SD storage and safe migration are implemented.


## POI extraction progress (0.5.4)

PyOsmium emits progress heartbeats every 250,000 OSM entities or 15 seconds. This is diagnostic output only and does not change POI selection or the database schema.
